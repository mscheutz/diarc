The human may provide various different types of input, whether it is giving the system an instruction, asking it a question, or providing it with information. No matter the type of input, the desired semantic form that the system can understand is called a "predicate". A "predicate" takes the form "<name>(<arguments>)" where <name> is simply a string, while <arguments> can be any number (0 to N) of symbols or nested predicates. Symbols are strings which may or may not have an associated type. Symbol types are denoted by a string following a colon. For example, an untyped symbol could be "testSymbol", while a typed symbol could be "testSymbol:testType". The type defines the set of values assignable to that argument. For example, an argument denoted as ?item:type1 in a semantic signature has the variable name ?item and type type1. The variable name is a placeholder to be replaced with the supplied value from the instruction, the type type1 denotes that the chosen value must be defined as a type1. If the user seems to supply a value for an argument which is not present in the current set of known entities of that type, there is no valid predicate to represent the input. In contrast, an argument denoted simply as, for example, ?varName has no type and does not have a restricted set of possible inputs.

Each specific type of user input (instruction, question, information) has a different set of valid predicate forms that can be mapped to. They will be described below:
###
Action Semantics:
Action semantics are used when the user is giving the system a direct instruction of an action it wants it to perform. The type of input in this case is INSTRUCT. Below is the list of action signatures known to the system, along with a description of the corresponding action.
##
goToLocation(?destination:location)
Description: The robot will navigate through the map to end up at location ?destination.
#
follow()
Description: The robot will use its camera to detect the person instructing this action and follow them until told to stop.
#
say(?words)
Description: The robot will use its speaker to say the given words out loud.
#
stopFollow()
Description: Related to the follow() action, the robot will stop following the user.
#
escortToLocation(?name, ?destination:location)
Description: The robot will immediately ask ?name to acknowledge that they should follow it from where it is currently located, then travels to ?destination once receiving confirmation.
#
escortFromToLocation(?name, ?start:location, ?destination:location)
Description: The robot will escort ?name from ?start to ?destination. The robot will first travel to ?start, then ask for ?name to acknowledge that they should follow the robot, then travel to ?destination while ?name follows.
#
saveLocation(?name)
Description: The robot will save a location at its current coordinates on the map under the label ?name. This location can be used for future navigation actions, such as goToLocation and escort variations.
#
saveLocationsToFile()
Description: The robot will write its current set of saved locations to a file such that it can load them on next startup without having to be re-saved.
#
definePatrolPath(?name)
Description: The robot will begin in a targeted conversation with the user to define a new path of locations under the label ?name, which the robot can later use for patrol tasks.
#
definePatrolPath()
Description: Same as the definePatrolPath(?name) action, but the label of the patrol path is not supplied in the instruction. This version of the action will additionally ask the user to supply the name of the path.
#
patrol(?pathName:path, ?actionName)
Description: The robot will navigate between all the locations included in the path ?pathName, and perform the action corresponding to ?actionName at each location. ?actionName is untyped, but the set of valid values here is only the name any known action semantic form (for example, wifiEvaluation or takePhoto).
#
wifiEvaluation(?location:location)
Description: The robot will measure the strength of a wifi signal at ?location and save the results for a later report.
#
reportWifiForLocation(?location:location)
Description: The robot will report the wifi signal quality at ?location measured the last time it visited ?location and ran wifi evaluation.
#
reportWifiForPatrol(?pathName:path)
Description: The robot will report the wifi signal quality at every location in patrol path ?patrol.
#
takePhoto(?location:location)
Description: The robot will take a photo at ?location and include it in a report to be sent to the user.
#
sit()
Description: The robot will sit.
#
stand()
Description: The robot will stand
#
deliver(?objectName, ?location:location)
Description: The robot will deliver ?objectName to ?location.
#
goHome()
Description: The robot will go to its home dock, where it can wait on standby and charge.
#
scheduleGoal()
Description: The robot will begin in a targeted conversation with the user to schedule any of the actions in this list to occur at a specific time in the future. The conversation will include questions about what the action is, when the user would like it to occur, and whether the action should be repeated on any time interval.
#
modifyScheduledGoal()
Description: The robot will begin in a targeted conversation with the user to modify the timing of a goal which was previously scheduled through the scheduleGoal() action. This conversation will include choosing the scheduled goal to modify and how to adjust its scheduled timing.
#
listScheduledGoals()
Description: The robot will tell the user its current list of scheduled goals which have yet to be performed.
#
cancelSystemGoals()
Description: The user is instructing the robot to stop whatever its currently doing. If stopping this way, it will completely discard any notion of what it was doing. It cannot be later resumed.
#
suspendSystemGoals()
Description: The user is instructing the robot to pause whatever its currently doing. If stopping this way, it will stay in a state where ths paused action can later be resumed and other actions will not begin until this one is resumed or fully canceled.
#
resumeSystemGoals()
Description: The user is instructing the robot to resume its current task which was paused through suspendSystemGoals(). If there are no currently paused task, this action will do nothing.
#
learnNewTask()
Description: the user is instructing the robot that they will begin teaching the system a new action. This will be done by having the user describe a sequence of actions to be performed, and the system remembering said action sequence.
#
endActionLearning()
Description: To be used after learnNewTask(), the user is instructing the robot that they are finished describing the action sequence of the new task. At this point the learning phase will end and the new action will be ready for execution.
#
describeCurrentLocation(?name)
Description: The robot will describe the current location it understands itself to be located at.
#
describeCurrentGoal()
Description: The robot will report what its current task is.
#
describePendingGoals()
Description: The robot will report what its pending tasks are. Pending tasks are not scheduled tasks, they are tasks which will be executed immediately in succession when the currently pursued task is complete.
#
describeAllKnownLocations()
Description: The robot will list all locations it currently has saved.
#
describeAllKnownPatrolPaths()
Description: The robot will list all patrol paths it currently has saved.
#
describeAllLocationsOnPatrolPath(?pathName:path)
Description: The robot will list all locations included along the saved patrol path under the name ?pathName.
#
repeatLastQuestion()
Description: The robot will repeat the last question it asked which the user still has yet to answer.

Reply Semantics:
Reply semantics are used when the user is answering a question from the system. The type of input in this case is REPLY. reply semantics can be any valid predicate, but typically take the form <typeOfInformation>(<valueOfInformation>). Below is the list of reply semantics the system is able to parse, along with a description of what is being conveyed in each case:
##
val(yes)
Description: The user is responding to a question affirmatively. Examples are yes, yeah, I agree, of course.
#
val(no)
Description: The user is responding to a question negatively. Examples are no, nah, I don't think so, definitely not.
#
location(?location:location)
Description: The user is giving an answer by referencing a known location ?location.
#
location(none)
Description: The user is responding to a question asking for a specific location by stating that they have supplied all the locations they want to. This usually occurs in the case of patrol path definitions.
#
taskPredicate(?actionPredicate)
Description: The user is giving an answer by referencing valid action semantics ?actionPredicate. A user instructing this may look very similar to a user simply instructing a certain action, but the conversation history between the robot and the user can inform whether the chosen semantic type are action semantics or the reply semantics shown here. In this case, the inner ?actionPredicate should be a fully populated form of one of the action semantics listed above.
#
time(?number, ?type)
Description: The user is answering a question by supplying either a specific clock time, or time interval. In the case of clock time, ?number will be a time in the form of HH:MM and ?type will either be am or pm. For example "3:30 p.m." should parse to time(3:30,pm). In the case of a time interval, ?number will be any positive whole number and ?type will be one of SECONDS, MINUTES, HOURS, or DAYS. For example, "fifteen minutes" should parse to time(15,MINUTES).
#
timingOf(?timingType)
Description: The user is responding to a question asking about which timing aspect of a scheduled goal they want to modify. The only two valid values for ?timingType are interval or execution. Interval is the delay at which a repeating scheduled goal should be repeated. Execution is the timing of the first execution of that goal before subsequently executing on an interval.
#
abort(question)
Description: These are universal semantics to represent when the user is declining to answer the question. Examples are "nevermind", "forget about it", and "im not answering that".
#
taskName(?name)
Description: Prompted by the learnNewTask action, the user is answering a question from the system about what the to-be-learned task should be called. ?name has no restriction on possible values. This form will generally follow a question in the conversation history asking "What is the name of the task?".
#
pathName(?name)
Description: Prompted by the definePatrolPath() action, the user is answering a question from the system about what the to-be-learned path should be called. ?name has no restriction on possible values. This form will generally follow a question in the conversation history asking "What is the name of the path?".
#
option(?number)
Description: Prompted to select from a list of numbered options, the user is answering which of those options they want to select. ?number is expected to be an integer.
