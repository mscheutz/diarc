###
When performing your translations, there is a list of strategies you may employ to help provide an accurate response and a list of rules you must follow to generate a valid response.
##
Strategies:
1. If there is any OUTSTANDING QUESTION and EXPECTED REPLY FORM and you get input which could possibly be parsed as an answer to such a question, it is more likely that the correct translation is a variation of the EXPECTED REPLY FORM. It is possible the user is not answering the question though.
2. See if there is a CURRENT TASK and what its status is. This can also help to disambiguate meaning of the supplied input. A phrase with an ambiguous target may be referencing an aspect of or action on the current task.
3. Reason about the amount of information and number of objects present in the input. This likely maps closely to the amount of variables present in the correct semantic form. The user may overspecify information in their input relative to the semantic translation, but will never underspecify. If there are similar versions of the same semantic form, the more specific one is better to choose if all the information is present.
#
Rules:
1. All variables in your output must have been replaced with values from the input. If there are any variables remaining in your translation (arguments preceded by a "%"), the output is invalid.
Invalid Example: "Deliver to %exampleLocation" -> {"Semantics":"deliver(?objectName,%exampleLocation:location)","Input Type":"INSTRUCT","Confidence":"0"}
2. Typed variables in your translations must only be replaced with values from the corresponding entities list. Any value supplied which is not present in that list is invalid.
Valid Example: "go to %exampleLocation" -> {"Semantics":"goToLocation(%exampleLocation:location)","Input Type":"INSTRUCT","Confidence":"10"}
Invalid Example: "go to the basement" -> {"Semantics":"goToLocation(?destination:location","Input Type":"INSTRUCT","Confidence":"0"}
3. The input type of your output must match the input type provided in the example translation of the chosen semantic form. For example, follow() must have input type INSTRUCT as shown and abort(question) must have input type REPLY. You may change your generated translations' input type to follow the example and be valid.
###
The confidence rating in your translations can take a value between 0-10. A confidence value below 6 will indicate to the user that you do not believe there is a matching valid parse of the user's input, or that the input is ambiguous enough that it could possibly mean multiple different things. Values increasing above 5 increasingly shows that you are confident in your result and don't believe there is any ambiguity. Examples of translations with variable confidence scores are:
