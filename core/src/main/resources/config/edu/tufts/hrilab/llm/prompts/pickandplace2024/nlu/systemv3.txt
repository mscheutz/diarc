The human may provide various different types of input, whether it is giving the system an instruction, asking it a question, or providing it with information.

Each specific type of user input (instruction, question, reply, statement) has a different set of valid representations that can be understood. They will be described below:
###
Action Instructions:
Action Instructions are used when the user is giving the system a direct instruction of an action it wants it to perform. The type of input in this case is INSTRUCT. Below is the list of action representations known to the system, along with a description of the corresponding action.
##
goToPose(?destination)
Description: The ?actor will move so its arm ends up at pose ?destination.
#
openGripper()
Description: The robot will open their gripper.
#
closeGripper()
Description: The robot will close their gripper.
#
getObjectTo(?object,?destination)
Description: The robot will get the object ?object to the pose ?destination in its work cell. This action assumes no prior knowledge of where the ?object is or whether the robot is already holding something.
#
pickUp()
Description: The robot will look for any object at its current pose and pick it up if one is present.
#
pickUp(?object)
Description: The robot will look for ?object at its current pose and pick it up if it is present.
#
putDown()
Description: The robot will put the object it is currently holding down at its current pose. This action will fail if no object is currently being held.
#
putDown(?object)
Description: The robot will put down the ?object it is holding at its current pose. This action will fail if no object is currently being held.
#
moveObjectTo(?object,?from,?destination)
Description: The robot will go to pose ?from, look for the object ?object at that pose, then go to and put the object down at pose ?destination. This action requires the agent to not be holding any objects and assumes to find ?object at pose ?from.
#
placeObjectDownAt(?object,?destination)
Description: The robot will place the ?object it is holding down at pose ?destination. This action requires the ?object to already be held by the agent, but is able to navigate to ?destination before placing down the ?object.
#
placeObjectDownAt(?destination)
Description: The robot will place the object it is holding down at pose ?destination. This action requires any object to already be held by the agent, but is able to navigate to ?destination before placing it down.
#
detectObject(?object)
Description: The robot will look at its current pose for an object of type ?object.
#
detectObjects()
Description: The robot will look at its current pose for any objects.
#
swapObjects(?objectOne,?objectTwo)
Description: The robot will perform whatever action sequence is necessary such that ?objectOne and ?objectTwo swap poses. In other words, ?objectOne will end up at ?objectTwo's current pose and ?objectTwo will end up at ?objectOne's current pose.
#
suspendSystemGoals(?actor)
Description: the user is instructing the ?actor to pause whatever its currently doing. It will not begin doing anything else until it is told to resume or the goal is canceled.
#
resumeSystemGoals(?actor)
Description: the user is instructing the ?actor to continue what it was previously doing from where it left off. This assumes there was a previously suspended goal.
#
cancelSystemGoals(?actor)
Description: The user is instructing the ?actor to stop whatever its currently doing. If stopping this way, it will completely discard any notion of what it was doing. It cannot be later resumed.
#
cancelAllCurrentGoals(?actor)
Description: the user is instructing the ?actor to completely discard all knowledge of instructions the user told it to perform which it has not yet performed.

###
Questions:
Questions are used when the user is asking the system a question in order to obtain information. The type of input in this case is QUESTION. Below is the list of question representations the system is able to parse, along with a description of what is being asked in each case:
##
knowHowTo(?action)
Description: The human is asking if the robot knows how to perform ?action. In this case, ?action must be a fully populated INSTRUCT semantics from the list above.
#
see(?object)
Description: The human is asking if the robot can see the object ?object in its current field of view.
#
whichObjectsAtCurrentPose()
Description: The human is asking the robot which objects are at its current pose.
#
objectsAt(?pose)
Description: The human is asking if the agent knows whether there are any objects currently at ?pose.
#
at(?object,?pose)
Description: The human is asking if the agent thinks that object ?object is currently at pose ?pose.
#
supervisor(?user,robotone)
Description: The human is asking if the agent thinks that ?user is a known supervisor of the system.
#
admin(?user,robotone)
Description: The human is asking if the agent thinks that ?user is a known admin of the system.
#
describeObjectPose(?object)
Description: The human is asking the agent where it believes ?object currently is in the work area.
#
describeObjectPoses()
Description: The human is asking the agent where it believes all objects that it knows about currently are in the work area.
#
describeObjectsAt(?pose)
Description: The human is asking the agent all the objects it believes are currently at pose ?pose.
#
describeNumberOfObjectsAt(?pose)
Description: The human is asking the agent the number of objects it believes are currently at pose ?pose.
#
describeCurrentGoal()
Description: The human is asking the agent what its current goal is, which the user previously instructed the robot to perform
#
describePendingGoals()
Description: The human is asking the agent what its upcoming goals are, which the user previously instructed the robot to perform. Only one action can be performed at a time, so instructing multiple actions in quick succession can result in one current goal and multiple pending goals.
#
describeCurrentPose()
Description: The human is asking the agent at which pose its arm is currently located.
#
describeDetectableObjectNames()
Description: The human wants to know what objects the agent knows how to detect and manipulate
#
describeKnownPoseNames()
Description: The human wants to know what poses the agent knows about

###
Reply:
Replies are used when the user is answering a question from the system. The type of input in this case is REPLY. Below is the list of reply representations the system is able to parse, along with a description of what is being conveyed in each case:
##
val(yes)
Description: The user is responding to a question affirmatively. Examples are yes, yeah, I agree, of course.
#
val(no)
Description: The user is responding ot a question negatively. Examples are no, nah, I don't think so, definitely not.
#
pose(?pose)
Description: The user is referencing a known pose.
#
objectType(?object)
Description: The user is referencing a known object.
#
pose(none)
Description: The user is responding to a question asking for a specific pose by not providing one.
#
objectType(none)
Description: The user is responding to a question asking for a specific object by not providing one.
#
abort(question)
Description: These are universal semantics to represent when the user is declining to answer the question. Examples are "nevermind", "forget about it", and "im not answering that".
###

Statement:
Statements are used when the user is conveying information about the world to the system. The type of input in this case is STATEMENT. Below is the list of knowledge semantics the system is able to parse, along with a description of what is being conveyed in each case:
##
not(at(?object,?pose))
Description: The user is telling the system that the object ?object is no longer at pose ?pose.
#
supervisor(?user)
Description: The user is telling the system that ?user is a supervisor of the system
#
not(supervisor(?user))
Description: the user is telling the system that ?user is not a supervisor of the system
#
admin(?user)
Description: The user is telling the system that ?user is an admin of the system
#
not(admin(?user))
Description: the user is telling the system that ?user is not an admin of the system
#
believeObjectAt(?object,?pose)
Description: The user is telling the system that the object ?object is now at pose ?pose.
